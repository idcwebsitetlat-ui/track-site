# השרת של אתר המסלול (Google Apps Script)

הקוד הזה רץ אצל Google, בחשבון idc.website.tlat@gmail.com. הוא עושה שלושה דברים:

- **כניסה:** בודק שם פרטי ושם משפחה מול הלשונית "סטודנטים" בגיליון הפרטי, ומחזיר לאתר רק כן או לא. אם השם נמצא, האתר מקבל אסימון כניסה שתקף ל-30 יום.
- **תוכן:** שולח לאתר את כל הלשוניות של גיליון התוכן, חוץ מ"מקרא". הוא משמיט שורות דוגמה, שורות שמסומנות "פעיל = לא" או "זמין = לא", וסקרים שעוד לא נפתחו או שכבר נסגרו. התוכן נשמר בזיכרון מטמון ל-5 דקות, ולכן שינוי בגיליון מופיע באתר תוך 5 דקות לכל היותר.
- **פניות:** רושם פנייה בלשונית "פניות" עם מספר רץ (0001, 0002…), שולח מייל התראה, ומחזיר לאתר את מספר הוואטסאפ ואת נוסח ההודעה.

## הקמה (פעם אחת, כרבע שעה)

1. **פותחים פרויקט:** נכנסים ל-https://script.google.com בחשבון idc.website.tlat@gmail.com, לוחצים "פרויקט חדש" ונותנים לו את השם "אתר המסלול - שרת".
2. **מדביקים את הקוד:**
   1. בגלגל השיניים (Project Settings) מסמנים "Show appsscript.json manifest file in editor".
   2. חוזרים לעורך (Editor). בקובץ `appsscript.json` מחליפים את כל התוכן בתוכן של `appsscript.json` מכאן.
   3. בקובץ `Code.gs` מחליפים את כל התוכן בתוכן של `Code.gs` מכאן.
   4. שומרים.
3. **הגיליונות:** המזהים של שני הגיליונות כבר כתובים בראש `Code.gs`, ולא צריך להגדיר אותם. אם יוצרים פעם גיליון חדש במקום אחד מהם, מחליפים שם את המזהה: החלק בכתובת של הגיליון שבין `/d/` ל-`/edit`.
4. **הרצה ראשונה ואישור הרשאות**

   בשלב הזה מריצים את הקוד פעם אחת, כדי ש-Google תאשר לו לגשת לגיליונות ולשלוח מייל.

   1. בשורת הכלים שמעל הקוד יש כפתור **Run** (בעברית: "הפעלה"). מימין לו יש רשימה נפתחת עם שם של פונקציה. פותחים אותה ובוחרים **setup**.
   2. לוחצים **Run**.
   3. נפתח חלון "Authorization required". לוחצים **Review permissions** ובוחרים את החשבון idc.website.tlat@gmail.com.
   4. מופיע מסך עם הכותרת "Google hasn't verified this app". זה תקין, כי Google מציגה אותו לכל קוד שאדם כתב לעצמו.
      1. לוחצים על הקישור הקטן **Advanced** בפינה השמאלית התחתונה.
      2. לוחצים על הקישור שמופיע מתחתיו: **Go to אתר המסלול - שרת (unsafe)**.
   5. במסך הבא מופיעה רשימה של מה שהקוד יוכל לעשות: לגשת לגיליונות ולשלוח מייל. אם יש תיבות סימון, מסמנים **Select all**, ואז לוחצים **Continue** או **Allow**.
   6. בתחתית המסך נפתח חלון **Execution log**. אמורות להופיע בו שורות כאלה:
      ```
      נוצר TOKEN_SECRET
      גיליון פרטי: 40 סטודנטים פעילים
      גיליון תוכן: מקרא, עדכונים, מועדים, ...
      מייל להתראות: idc.website.tlat@gmail.com
      מספר וואטסאפ: חסר
      ```
      אם במקום זה מופיעה שורה אדומה, מעתיקים אותה ושולחים ל-Claude.

5. **בדיקה**
   1. באותה רשימה נפתחת, ליד Run, בוחרים הפעם **testLoginAndContent** ולוחצים **Run**.
   2. ב-Execution log אמורות להופיע שלוש שורות שמסתיימות ב-`true`. אחריהן מופיעה שורה לכל לשונית, עם מספר השורות שבה:
      ```
      כניסה: true
      כניסה בסדר הפוך: true
      שם שלא ברשימה נדחה: true
      עדכונים: 0 שורות
      מועדים: 14 שורות
      ...
      ```
   3. אם אחת השורות מסתיימת ב-`false`, או שמופיעה שורה אדומה, מעתיקים את מה שכתוב ב-Execution log ושולחים ל-Claude.

6. **פרסום, כדי שהאתר יוכל לפנות לשרת**
   1. בפינה הימנית העליונה יש כפתור כחול **Deploy** (בעברית: "פריסה"). לוחצים עליו ובוחרים **New deployment** ("פריסה חדשה").
   2. נפתח חלון. בצד שמאל, ליד "Select type", יש סמל של גלגל שיניים. לוחצים עליו ובוחרים **Web app** ("אפליקציית אינטרנט").
   3. ממלאים שלושה שדות:
      - **Description:** כותבים `גרסה 1`.
      - **Execute as** ("הפעלה בתור"): בוחרים **Me (idc.website.tlat@gmail.com)**.
      - **Who has access** ("למי יש גישה"): בוחרים **Anyone** ("כל אחד"). לא "Anyone with Google account".
   4. לוחצים **Deploy**. אם Google שוב מבקשת הרשאות, מאשרים כמו בשלב 4.
   5. מופיע חלון עם השדה **Web app URL**. זו כתובת ארוכה שמתחילה ב-`https://script.google.com/macros/s/` ומסתיימת ב-`/exec`.
   6. לוחצים **Copy** ליד הכתובת, שולחים אותה ל-Claude, ולוחצים **Done**.

"Anyone" אומר שכל אחד יכול לשלוח בקשה לשרת. זה לא אומר שכל אחד יכול לראות מידע: בלי שם שמופיע ברשימה השרת לא מחזיר תוכן, והוא אף פעם לא מחזיר את רשימת השמות או את הפניות.

## חיבור היומן של האוניברסיטה (שינויים בשיעורים)

השרת קורא את היומן האישי מתחנת המידע פעם בשעה. הוא מוצא מפגשים שחורגים מהמועד הקבוע של הקורס, ושולח אותם לאתר:
- **בזום:** מפגש שמתקיים בזום ולא בכיתה.
- **שעה אחרת:** אותו יום, שעה אחרת.
- **חדר אחר:** אותו יום ושעה, חדר אחר.
- **מפגש נוסף או שהוזז:** יום אחר לגמרי.
- **מבוטל:** מפגש שהסטטוס שלו ביומן הוא לא "מתקיים".

הקישור ליומן כולל אסימון אישי, ולכן הוא **לא** כתוב בקוד אלא נשמר בהגדרות הפרויקט:

1. בגלגל השיניים, תחת Script properties, מוסיפים מאפיין:
   - **Property:** `UNIV_CALENDAR_URL`
   - **Value:** הקישור ליומן מתחנת המידע, זה שמתחיל ב-`https://yedion.runi.ac.il/`.
2. מחליפים את `appsscript.json` ואת `Code.gs` בגרסאות החדשות מכאן. ב-`appsscript.json` נוספה הרשאה לפנות לכתובות חיצוניות.
3. ברשימה שליד Run בוחרים **testLessonChanges** ולוחצים Run. Google תבקש שוב הרשאות, בגלל ההרשאה החדשה. מאשרים כמו בפעם הראשונה.
4. ב-Execution log אמורה להופיע השורה "שינויים בשיעורים מהיום והלאה", ואחריה רשימת השינויים.
5. מפרסמים גרסה חדשה, לפי השלבים בסעיף הבא.

**מגבלות:**
- היומן הוא של אלון, ולכן הוא מראה את הקבוצות שלו. סטודנט בקבוצת תרגול אחרת לא יראה שינויים בתרגול שלו.
- שיעור שנמחק מהיומן לגמרי, במקום שיסומן כמבוטל, לא יזוהה כשינוי.

## עדכון הקוד בהמשך

1. מדביקים את הגרסה החדשה ושומרים.
2. בוחרים Deploy, ואז Manage deployments.
3. לוחצים על העיפרון, ובשדה Version בוחרים New version, ואז Deploy.

כך הכתובת נשארת אותה כתובת. **לא** יוצרים New deployment, כי זה יוצר כתובת חדשה.
